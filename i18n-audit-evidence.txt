1. KEY-PARITY (de vs en)
------------------------
Result: ✅ PASS — de.ts and en.ts have IDENTICAL key sets:
  de = 1189 keys, en = 1189 keys, onlyDe = 0, onlyEn = 0
  (verified by i18n-scan.ts via Object.keys(de) vs Object.keys(en);
   the "typeof de" type annotation additionally enforces parity at compile time).
No key present in one dictionary but missing in the other → no fallback-to-English at runtime.

in BOTH dictionaries. React type names (Dispatch, FormEvent, …) and lambda
property accesses (t.id, t.done, …) are excluded as non-i18n references.

6. TOASTS / ALERTS / CONFIRMS / CLIENT ERROR PATHS
---------------------------------------------------
All alert()/confirm()/toast/setError calls audited — every one already used
localized t.* keys. Two client catch-blocks leaked raw server Error.message
(English) to the user; both now show localized text (t.common_unknown_error /
t.perf_load_failed). Server-side English literals (LLM prompts, validation
messages, console logs) are dev-facing and never rendered — reported as INFO
by the scan (63 literals), not failures.
